# 프로젝트 구조 가이드

앞모델과 뒷모델 담당자는 같은 버전 이름으로 학습 자료와 추론 결과물을 관리한다. 다른 팀원이 해당 버전의 학습을 재현하고, 추후 GUI에서 버전 하나를 선택해 서로 맞는 두 모델과 대상 DB를 함께 불러올 수 있도록 한다. 아래 경로는 저장소 루트 기준이다.

## 앞·뒷모델 공통 버전 규칙

`<버전>`은 앞·뒷모델에 공통으로 붙이는 버전 이름이고, `<실험>`은 개별 학습 실행을 구분하는 이름이다.

| 위치 | 함께 보관할 내용 |
| --- | --- |
| `data/<버전>/` | 앞모델의 질문·라벨과 뒷모델의 일반화 질문·SQL 데이터셋, 두 모델의 생성·분할·학습 옵션을 함께 보관한다. 팀에서 재현에 사용할 데이터셋과 옵션은 이 폴더에 커밋한다. |
| `data/<버전>/generated/` | 로컬에서 생성한 데이터셋을 둔다. 이 폴더 안의 파일은 `.gitignore`의 `/data/*/generated/` 규칙으로 Git에서 제외된다. |
| `runs/` | 학습 중 생성되는 실험별 임시 폴더를 보관한다. |
| `models/<버전>/` | GUI에서 선택한 버전의 `front.gguf`, `back.gguf`, 대상 DB를 한 폴더에서 불러올 수 있도록 함께 보관한다. 전처리 사전 등 추론에 필요한 파일도 여기에 둔다. |

독립 평가셋이나 스키마 매핑용 DB·사전을 사용했다면 같은 데이터 버전에 보관한다. 버전 폴더에 실제 실행 명령과 코드 커밋을 기록하면 생성 쌍 수, 분할 비율, 단계별 시드, 장치, 입출력 경로를 다시 확인할 수 있다.

## 프로젝트 디렉터리 구조

```text
capstone-sql-mapper/
├── front.py                # 앞모델 명령 진입점 (구현 예정)
├── back.py                 # 뒷모델 명령 진입점
├── requirements.txt        # Python 실행 의존성
├── src/
│   ├── data_generation/    # 모델별 데이터 생성과 학습·검증 분할
│   │   ├── build_front.py  # 앞모델 학습셋·검증셋 구성 (구현 예정)
│   │   └── build_back.py   # 일반화 질문·SQL 쌍을 학습셋·검증셋으로 분할
│   ├── back/               # 학습과 추론이 공유하는 뒷모델 구현
│   ├── front/              # 앞모델 구현 예정
│   ├── preprocessor/       # 전처리기 구현 예정
│   ├── mapper/             # DB 태그 일반화와 SQL 복원 기록 생성
│   └── postprocessor/      # 후처리기 구현 예정
├── training/
│   ├── back/               # 뒷모델 학습·평가·GGUF 내보내기
│   └── front/              # 앞모델 학습 코드용 빈 폴더
├── inference/
│   ├── back.py             # GGUF로 단일 질문 또는 JSON 파일 추론
│   └── mapper.py           # 앞모델 출력 JSON을 뒷모델 입력으로 변환
├── data/
│   └── <버전>/             # 앞·뒷모델의 옵션과 공유할 데이터셋
│       └── generated/      # 로컬 생성 데이터셋 (Git 제외)
├── runs/                   # 학습 중 생성되는 임시 폴더
│   ├── back/<실험>/
│   └── front/<실험>/
├── models/
│   └── <버전>/             # 두 모델의 최종 GGUF와 대상 DB
├── tests/                  # 데이터 생성·분할, 모델, 학습, 내보내기, 추론 테스트
└── docs/                   # 실행·옵션 가이드, 데이터 규칙, 팀원 역할
```

## 매퍼 실행

앞모델 추론 결과의 `input`은 앞모델에 넣은 질문, `output`은 DB 태그 문장이다.
이 JSON 배열을 저장소 루트에서 변환한다.

```bash
python -m inference.mapper --input front_results.json --output back_inputs.json
```

결과의 `input`은 `back.py infer --input`에서 읽을 일반화 질문이다. `mapping.tables`와
`mapping.columns`에는 일반화 이름에서 실제 이름으로의 대응을 저장한다. `mapping.values`는
`[TABLE1.COL2, numeric, #1]` 같은 전체 값 태그를 키로 쓰고 `10 dollars` 같은 원문 값을 보관한다.
입력 레코드에 `id`가 있으면 결과에도 남긴다.

원문과 태그 문장의 태그 밖 표현을 맞춰 조건값의 위치를 찾는다. 대소문자·공백과 태그 직전의
`a`/`an` 차이는 허용한다. 조건값의 위치가 여러 가지로 해석되거나 문장의 표현이 어긋나면 해당
행 번호와 오류를 출력한다. SQL 복원 단계는 `back_inputs.json`의 대응표를 뒷모델 결과와 함께 사용한다.

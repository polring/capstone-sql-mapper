# 뒷모델 옵션 가이드

옵션 파일은 원하는 폴더에 보관할 수 있다. 생성할 때는 `--sql-types`로 유형 비율 파일을, 학습할 때는 `--config`로 모델·학습 설정 파일을 매번 지정한다. 두 JSON 모두 최상위의 `description`에 용도를 적거나 빈 문자열(`""`)을 두거나 키를 생략할 수 있다. 실행 순서와 PowerShell 명령은 [뒷모델 실행 가이드](<./뒷모델 실행 가이드.md>)에서 확인할 수 있다.

## 기본값으로 시작하는 옵션 파일

- [data/example/sql_types.json](../data/example/sql_types.json)은 네 SQL 유형과 모든 세부 조합의 비율을 `null`로 두어 자동 배정한다. 일반 예시만 생성하도록 `ordinary`는 `1`, `contrast`는 `null`로 두었다.
- [data/example/train.json](../data/example/train.json)은 모델·학습 파라미터를 모두 표시한다. 원하는 값만 채우면 나머지는 실행 모드에 맞는 기본값을 사용한다. 경로·시드·장치는 CLI에서 지정한다.

## 데이터 생성 옵션 JSON

| 키 | 필수 여부 | 의미 |
| --- | --- | --- |
| `family_percent` | 필수 | 전체 쌍 중 일반 조회(`rows`), 단순 집계(`aggregate`), 그룹 조회(`group`), 스칼라 서브쿼리(`scalar`)에 배정할 백분율. 생략한 유형은 0%다. 고정 비율의 합은 100%여야 하며, `null`을 지정한 유형이 있으면 남은 비율을 그 유형끼리 균등하게 나눈다. |
| `example_weights` | 필수 | 일반 예시(`ordinary`)와 비교 경계·정렬 방향 등 한 가지 의미를 바꾼 대조 예시(`contrast`)의 상대 가중치. 생략하거나 `null`로 둔 쪽은 0이며 적어도 한쪽은 양수여야 한다. |
| `subtype_percent` | 선택, 기본 `{}` | 각 SQL 유형 **안에서** 세부 조합에 배정할 백분율. 개별 조합을 `0`으로 지정하면 제외한다. 생략하거나 `null`로 둔 조합은 남은 비율의 자동 배정 대상이다. |

세부 유형 키는 아래처럼 읽는다. 지정한 조합에서 만들 수 있는 서로 다른 질문이 요청량보다 적으면 해당 비율이나 SQL당 질문 수를 조정한다.

| 유형 | 세부 유형 키 예시 | 생성할 SQL |
| --- | --- | --- |
| `rows` | `where0/plain` | `WHERE`, `ORDER BY`, `LIMIT` 없는 기본 조회 |
| `rows` | `where0/limit` | 조건 없이 `LIMIT`으로 반환 행 수를 제한한 조회 |
| `aggregate` | `COUNT/where1` | 조건 한 개를 적용한 뒤 개수를 구하는 집계 |
| `group` | `SUM/where0/having:>/plain` | 그룹별 합계를 구한 뒤 `HAVING`으로 기준값을 초과한 그룹만 선택 |
| `scalar` | `AVG/>/inner0/outer1` | 바깥 쿼리의 값이 서브쿼리의 평균보다 큰지 비교. 서브쿼리에 추가 조건이 없고 바깥 쿼리에 추가 조건이 한 개 있음 |

## 학습 옵션 JSON

새 학습에서는 선택 설정을 생략하거나 값을 `null`로 두면 표의 기본값이 적용된다. `--resume`으로 재개하면 저장된 모델·학습 설정을 사용하며, `train_config.epochs`로 도달할 총 에폭 수를 늘릴 수 있다.

### 최상위 키

| 키 | 기본값 | 의미 |
| --- | --- | --- |
| `overfit` | `null` | 일반 학습은 검증셋으로 채점한다. 4 이상의 정수를 넣으면 네 SQL 유형에서 서로 다른 정답 SQL을 고르게 뽑아, 지정한 수의 학습 쌍 자체를 재현하는지 확인한다. |
| `threads` | PyTorch 환경값 | CPU 연산 스레드 수. 1 이상의 정수로 지정한다. |
| `eval_every` | 일반 학습 `1`, 재현 모드 `10` | 채점 간격(에폭). 일반 학습에서는 생략, `null`, `1`만 허용한다. |
| `eval_batch_size` | `32` | 채점 시 SQL을 동시에 생성할 질문 수. |
| `model_config` | `{}` | 토크나이저 어휘 크기와 디코더 구조를 정하는 객체. |
| `train_config` | `{}` | 배치 크기, 옵티마이저, 정밀도, 종료 조건을 정하는 객체. |

### `model_config`

| 키 | 기본값 | 의미 |
| --- | --- | --- |
| `vocab_size` | `4096` | 질문과 SQL이 공유하는 어휘 용량. 바이트·특수 토큰·고정 SQL 토큰을 배정한 뒤 남은 용량으로 질문 BPE를 학습한다. |
| `d_model` | `256` | 토큰 임베딩과 디코더 은닉 벡터의 차원. |
| `num_layers` | `8` | 디코더 블록 수. |
| `num_heads` | `4` | 블록당 어텐션 헤드 수. 헤드당 차원(`d_model / num_heads`)은 짝수인 정수여야 한다. |
| `ffn_dim` | `1024` | 블록 내부 피드포워드 신경망의 중간 차원. |
| `context_length` | `512` | 질문·SQL·특수 토큰을 합친 시퀀스의 최대 길이. 새 학습에서 더 긴 예시가 있으면 그 길이까지 늘린다. |
| `dropout` | `0.0` | 학습 중 어텐션에 적용하는 드롭아웃 확률. 0 이상 1 미만. |
| `eps` | `1e-6` | RMSNorm 계산을 안정화하는 양수. |
| `theta` | `10000.0` | RoPE 위치 인코딩의 주파수를 정하는 양수. |

### `train_config`

| 키 | 기본값 | 의미 |
| --- | --- | --- |
| `batch_size` | `8` | 한 배치에서 처리할 학습 쌍 수. |
| `accumulation_steps` | `4` | 가중치를 한 번 갱신할 때까지 그래디언트를 누적할 배치 수. 기본 설정에서는 갱신당 최대 32쌍을 사용한다. |
| `epochs` | 일반 `12`, 재현 `400` | 학습셋을 반복할 최대 횟수. 재개 시에는 이전 학습 횟수를 포함한다. |
| `lr`, `min_lr` | `0.001`, `0.0001` | 워밍업의 목표 학습률과 코사인 감소가 끝날 때의 최소 학습률. `0 < min_lr <= lr`이어야 한다. |
| `warmup_ratio` | `0.01` | 전체 가중치 갱신 횟수 중 학습률을 선형으로 올리는 구간의 비율. |
| `weight_decay` | `0.1` | AdamW가 가중치에 적용하는 감쇠 계수. |
| `beta1`, `beta2` | `0.9`, `0.95` | AdamW에서 그래디언트와 그래디언트 제곱의 이동평균을 각각 얼마나 유지할지 정하는 계수. |
| `eps` | `1e-8` | AdamW의 분모를 안정화하는 양수. |
| `max_grad_norm` | `1.0` | 가중치를 갱신하기 직전에 적용하는 그래디언트 노름 상한. |
| `patience` | 일반 `3`, 재현 `0` | 일반 학습에서 검증 성능 개선을 기다릴 연속 에폭 수. `0`이면 이 조기 종료 조건을 끈다. |
| `precision` | `"auto"` | `"auto"`는 BF16을 지원하는 CUDA GPU에서 BF16 혼합 정밀도, 그 외에는 FP32를 사용한다. `"fp32"`, `"bf16"`으로 직접 지정할 수 있다. |

## 단계별 CLI 옵션

모든 명령에서 `-h` 또는 `--help`로 사용법을 볼 수 있다. 상대 경로는 **명령을 실행한 폴더** 기준이다. 생성·분할·학습의 `--seed`는 각 단계에서 독립적으로 지정하는 정수다.

### 데이터 생성 · `src.data_generation.generalized_pairs.generate`

| 옵션 | 필수 여부·기본값 | 역할 |
| --- | --- | --- |
| `--count` | 필수 | 분할 전 생성할 질문·SQL 쌍 수. 0 이상의 정수. |
| `--sql-types` | 필수 | SQL 유형 비율이 담긴 생성 옵션 JSON 경로. |
| `--output` | 필수 | 원본 데이터셋을 쓸 JSON 경로. 생성이 끝나면 해당 파일을 교체한다. |
| `--seed` | 필수 | SQL과 질문 표현을 선택하는 시드. |
| `--max-questions-per-sql` | 선택, 자동 | 원본 SQL 하나당 생성할 서로 다른 질문 수의 상한. 직접 지정할 때는 1 이상의 정수를 쓴다. |

### 학습·검증 분할 · `src.data_generation.build_back`

| 옵션 | 필수 여부·기본값 | 역할 |
| --- | --- | --- |
| `--input` | 필수 | 생성한 원본 질문·SQL 쌍 JSON 경로. 분할 파일도 이 원본과 같은 폴더에 저장한다. |
| `--seed` | 필수 | 검증에 배정할 고유 정답 SQL을 선택하는 시드. |
| `--validation-ratio` | 선택, `0.05` | 유형별 고유 정답 SQL 중 검증에 배정할 비율. 0보다 크고 1보다 작아야 한다. 같은 SQL을 묻는 질문이 함께 이동하므로 질문 쌍 기준 비율은 달라질 수 있다. |

분할 파일명은 원본의 마지막 확장자를 떼고 `_back_train.json`과 `_back_validation.json`을 붙인다. 예를 들어 `data/questions.v1.json`을 분할하면 `data/questions.v1_back_train.json`과 `data/questions.v1_back_validation.json`이 생긴다.

### 학습 · `training.back.train`

| 옵션 | 필수 여부 | 역할 |
| --- | --- | --- |
| `--config` | 필수 | 모델·학습 옵션이 담긴 JSON 경로. |
| `--train-file` | `--data-dir`와 둘 중 하나 필수 | 분할한 학습 JSON 경로. 일반 학습은 같은 폴더에서 같은 원본명의 검증 JSON도 읽는다. |
| `--data-dir` | `--train-file`과 둘 중 하나 필수 | 학습 데이터셋 한 개가 들어 있는 폴더. 여러 데이터셋이 있으면 `--train-file`로 사용할 파일을 지정한다. |
| `--run-dir` | 필수 | 체크포인트 `best.pt`, `last.pt`와 학습 기록 `history.jsonl`을 저장할 실험 폴더. 새 실험은 새 경로를 사용한다. |
| `--seed` | 필수 | 모델 초기화, 에폭별 데이터 셔플, 재현용 학습 표본 선택에 쓸 시드. |
| `--device` | 필수 | `cpu`, `cuda`, `cuda:0` 등 PyTorch 장치. `gpu`는 CUDA를 사용하고, `auto`를 명시하면 CUDA 사용 가능 여부에 따라 장치를 선택한다. |
| `--resume` | 선택 | 재개할 `last.pt` 경로. 같은 분할 데이터와 체크포인트의 시드를 지정한다. |

### GGUF 내보내기 · `training.back.export_gguf`

| 옵션 | 필수 여부 | 역할 |
| --- | --- | --- |
| `--checkpoint` | 필수 | 내보낼 학습 체크포인트 경로. 보통 해당 실험의 `best.pt`를 선택한다. |
| `--output` | 필수 | F32 GGUF를 쓸 경로. 변환은 CPU에서 수행하며, 지정한 출력 파일이 있으면 교체한다. |

### GGUF 추론 · `inference.back`

| 옵션 | 필수 여부·기본값 | 역할 |
| --- | --- | --- |
| `--model` | 필수 | 내보낸 `capstone_sql` 규격 v3 F32 GGUF 경로. |
| `--device` | 필수 | `cpu`, `cuda`, `gpu` 중 하나. |
| `--question` | 단건 입력 | 일반화 태그 질문 한 개. 예측한 SQL을 터미널에 출력한다. `--input`과 둘 중 하나를 지정한다. |
| `--input` | 파일 입력 | 질문 목록 JSON 경로. 각 항목의 `input` 문자열을 순서대로 읽는다. |
| `--output` | 파일 입력 시 필수 | 원래 질문(`input`)과 예측 SQL(`output`)을 저장할 별도 JSON 경로. |
| `--batch-size` | 파일 입력 시 선택, `32` | 한 번에 추론할 질문 수. 1 이상의 정수. |

### 독립 평가 · `training.back.evaluate`

| 옵션 | 필수 여부·기본값 | 역할 |
| --- | --- | --- |
| `--checkpoint` | 필수 | 채점할 학습 체크포인트(`.pt`) 경로. |
| `--data` | 필수 | 질문과 정답 SQL이 담긴 독립 평가셋 JSON 경로. |
| `--device` | 필수 | 평가에 사용할 PyTorch 장치. 예를 들어 `cpu`, `cuda`, `cuda:0`을 지정한다. |
| `--batch-size` | 선택, `32` | 한 번에 채점할 질문 수. 1 이상의 정수. |
| `--threads` | 선택, PyTorch 환경값 | CPU 연산 스레드 수. |
| `--predictions` | 선택 | 질문별 예측과 채점 결과를 쓸 JSON 경로. 생략하면 터미널에 집계 점수만 출력한다. |
